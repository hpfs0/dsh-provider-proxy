## v1.1.1 (Data Integrity Hotfix)

数据完整性热修：修复一处会**把备份文件写残、把预设/路由写空、让流量静默改直连**的草稿合并缺陷，以及几处会让**页面结论与真实配置不符**的问题。

基于 `v1.1.0` 基线，**无配置迁移、无备份 Schema 变更**（文件仍是 `version: 2`），patch 级发布。

### 修复

- **整字典写盘按字段合并草稿 (P0)。**
  备份导出、预设增/改/删、幽灵路由清理三处此前都以 `{ ...stored, ...draft }` 生成整本字典。草稿条目只包含本次会话改过的字段，字典级 spread 会把整条记录替换成这个片段，写盘前再被 schema 默认值补齐：
  - 导出备份时，改过一个字段的卡片在文件里丢失 `host` / `port` / 凭据 / 域名规则，用它恢复等于把该路由关掉并清空地址；
  - 编辑预设 A 之后再添加/重命名/删除任意预设，A 的其余字段被写成空值，绑定 A 的卡片全部「配置被拒」——即不再经过任何代理；
  - 孤儿清理整表回写时，同样会截断本次会话编辑过的路由。
  现在统一走 `overlayDrafts()`：按条目、按字段合并，草稿只覆盖它真正携带的键。
- **自检与搜索不再复用已被替换的 dispatcher (P1)。**
  设置写入到 `loader/volatile-update` 之间，代理表里的路由仍由旧配置构建。自检此前只比较 `proxyOrigin`：改密码、改 `onlyHosts`/`bypassHosts`、改 `testTarget` 都保持同一 origin，于是「测试」仍用旧 dispatcher 探测，并把结论贴在新配置上（改对的密码仍报 407、新目标仍探测旧地址、改后的规则仍按旧判定走代理）。现在按完整配置身份（`routeFingerprint` + `testTarget`）比对，不一致就以当前设置重建；搜索分流则记录 dispatcher 对应的预设 id，不一致时短暂拒绝，**绝不从用户已经替换掉的预设发出**。
- **「测试」前先落盘预设草稿。** 卡片的端点来自所绑定的预设，但 flush 白名单不含预设写键，改完预设立刻点测试会测到旧值。白名单已补上预设命名空间。
- **恢复备份后清空自检结果。** 导入是整体替换配置，此前只清草稿，卡片继续显示上一个端点的延迟/状态/出口 IP；现在同时失效代次并清空结果，进行中的检查也不会回贴。
- **幽灵路由清理要求连续两次目录缺失。** 阈值由 1 改为 2：一次成功但暂不完整的目录读取（插件仍在加载、registry 返回部分列表）不再删除已保存的默认绑定。
- **导出提示不再显示 `undefined`。** 成功导出后引用了未定义的文案键，诊断面板出现「undefined已导出备份…」；文案已修正，并新增一条源级不变量用例（EN/ZH 键集合一致、每个被读取的 `t.<key>` 都有定义）。

### 行为变化

- 搜索分流在「设置写入 → 重建」的一瞬间会以「**搜索分流配置正在生效，请稍后重试**」拒绝一次，而不是从旧预设发出。这是刻意的 fail-closed：错误出口与拒绝相比，拒绝更接近用户刚表达的意图。
- 幽灵路由清理改为需要**两次连续**权威目录读取（挂载一次 + 10 秒轮询一次），用户感知上最多多等一个轮询周期。

### 验证与质量

- `npm run verify`：**482 个用例全绿**（v1.1.0 的 472 个 + 10 个新增回归用例）。
- 每一条修复都先有失败用例：三处草稿写盘出口、自检的凭据/目标/规则三种改法、搜索换绑、测试前落盘、恢复后清结果、两次缺失才清理、文案键一致性。
- `npm run typecheck`：TypeScript 0 错误。
- 打包清单不变：`npm pack --dry-run` 仍为 9 个文件。

### 升级与迁移

无需迁移。备份文件版本不变（`version: 2`），配置字段与默认值均未改动。若曾在旧版本里导出过「本次会话编辑过卡片」的备份，建议重新导出一次：那份文件可能已经缺少端点与凭据。

### 安装

桌面版（先完整打开一次桌面版以初始化 profile，再完全退出）：
```sh
dsh plugin --profile desktop add dsh-provider-proxy
```

Web 版：
```sh
dsh plugin --profile web add dsh-provider-proxy
```
