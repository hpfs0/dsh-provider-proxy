## v1.4.0 (High Availability & Failover)

高可用与请求级重试版本：在保持 fail-closed 安全边界的前提下，让代理主节点失联时可以按顺序切换至备用预设节点，并让瞬时建连失败与 502/503/504 具备可控的指数退避重试。

基于 `v1.3.0` 基线，备份文档从 `version: 3` 升级到 `version: 4`，minor 级发布。

### 新特性

- **主备代理多节点故障自动切换（N26）。** 默认代理、命名预设及自定义端点均可配置最多 3 个备用预设节点。主节点仅在连接建立阶段失败（如 `ECONNREFUSED`、`ETIMEDOUT`、`EHOSTUNREACH`、`ENETUNREACH`、`ConnectTimeoutError`）且请求体可安全重放时按顺序尝试备用节点；不安全的请求不会为了故障切换而重复发送。
- **配置继承。** 绑定默认代理或命名预设的卡片会继承该端点上的 `enableProxyFailover` 与 `backupProfileIds`；预设上的开关现在真正作用于使用它的卡片。路由级 `enableProxyFailover: true` 可强制开启。
- **备用链可见性。** 设置页会显示卡片实际生效的备用链及其来源；缺失预设、端点不完整、重复项、与主节点相同的备选会被标记并跳过。开启 Failover 但没有任何可用备用节点时会就地告警。
- **接管状态。** 备用节点接管成功后，卡片显示 `[故障切换: 上次请求经备用节点 <profileId>]`，紧凑行显示 `节点A（主） / 上次经 节点B`；仪表盘汇总当前有多少 provider 的上次请求由备用节点承接。主节点恢复后，后续请求会重新尝试主节点并自动撤销接管。
- **请求级智能指数退避重试（N29）。** 全局设置新增 `retryAttempts`（0~3，默认 0）与 `retryBackoffBaseMs`（默认 200 ms），使用 Full Jitter 指数退避。只对连接建立阶段失败或 502/503/504 且响应流尚未被调用方消费、请求体可安全重放的请求重试；4xx、407、`ECONNRESET`、调用方超时和不可重放 body 均不重试。
- **重试状态回显。** 发生重试时，卡片「最近调用」会追加 `· 重试 N 次`，无需翻 Host 日志确认。
- **备份升级至 Schema v4。** 导出文件新增主备切换与重试字段；v1/v2/v3 及无 version 的旧文件仍可导入，缺失字段按安全默认值补齐。

### 行为变化

- **预设/默认代理上的 Failover 开关会作用于绑定卡片。** 启用预设上的开关后，所有使用该预设的卡片都会继承备用链；升级后请先确认备用节点配置符合预期。
- **路由级 `false` 不会关闭已继承的开关。** 当前设置页在绑定预设/默认代理时没有 per-card 关闭入口；如需按卡片关闭，后续需要引入显式的 `inherit/on/off` 三态。
- **接管文案表示“上次请求”而非实时路由状态。** 主节点冷却期结束后，下一次请求仍会先尝试主节点；界面不会再声称当前一定处于接管中。
- **备份文件变为 `version: 4`。** 1.3.x 及更早版本会明确拒绝 v4 文件；降级前请先导出一份旧版兼容备份。
- **运行时依赖升级。** `undici` 从 `8.11.2` 升级到 `8.13.1`，修复依赖审计中的高危公告；代理与 SOCKS5/TLS 回归由完整测试套件覆盖。

### 已知限制

- **备用节点可达性不做主动探测。** 卡片重新测试与后台心跳仍只验证主节点；备用链展示的是配置有效性，不代表备用节点一定可达。这样保持现有的零额外流量原则。
- **故障切换只覆盖连接建立阶段。** 主节点返回 502/503/504 时由 N29 重试处理，不会因此切换到备用节点；这是为了避免把可能已到达上游的请求重复执行。
- **重试预算按一次请求共享。** 主节点与备用节点共用 `retryAttempts` 上限，不会为每个候选节点重新计数。

### 升级与迁移

1. 升级前建议在桌面版或 `dsh web` 的备份页导出一份现有备份。
2. 配置字段无需手工迁移；新字段缺失时按 `enableProxyFailover: false`、`backupProfileIds: []`、`retryAttempts: 0`、`retryBackoffBaseMs: 200` 补齐。
3. **如需降级到 1.3.x 或更早版本，请先导出 v3 兼容备份**；v4 文件会被旧版明确拒绝。
4. 升级后建议在「代理预设」页确认绑定卡片的备用链来源，并各执行一次主节点自检与真实请求。

### 安装

桌面版（先完整打开一次桌面版以初始化 profile，再完全退出）：
```sh
dsh plugin --profile desktop add dsh-provider-proxy
```

Web 版：
```sh
dsh plugin --profile web add dsh-provider-proxy
```
