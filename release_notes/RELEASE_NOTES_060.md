## v0.6.0

设置页收尾版：让 `testUrl` / `localDirect` 不再只能手改 YAML，让自检结果说得清
「到了哪里、返回了什么、是否来自缓存」，并让保存失败与危险诊断值真正可见、可信。
无 schema 变更，0.5.1 配置无需迁移；本版本不改变 `lastUse` / route token /
`lastChecks` 的语义。

### 新功能

- **全局设置（高级）。** 设置页新增折叠块，可直接编辑 `testUrl` 与 `localDirect`。
  `testUrl` 支持逗号 / 空格分隔的多个候选，按序回退，最多 5 个；留空时 Host 使用内置默认值。
  非法候选或超限只提示、不阻止保存。「恢复默认」写入明确默认 URL。
  `localDirect` 默认勾选；关闭后本机 / 内网目标也走代理。
- **自检结果可解释。** 卡片显示成功标记与延迟、`HTTP 401` 状态码、脱敏后的探测目标与 `缓存` 标记；
  失败时目标仍然可见。没有 `status` / `target` 的旧 Host payload 仍能正常渲染。
- **自检目标来源可解释。** 结果行标出这次用的是哪一级目标：
  `（本卡片自检目标）` / `（该 provider 的真实上游）` / `（全局自检地址）`。
  改 `testUrl` 后某张卡片没变，从此有了答案——该 provider 自己发布了真实上游，
  本就不读 `testUrl`；要覆盖它请在该卡片的「自检目标」里显式填写。
- **慢速成功不再显示成失败。** 延迟分档颜色只作用在延迟数字上，状态码与目标用普通标签色；
  一次 2646 ms 的成功检查此前整行变红，看起来像失败。
- **目标脱敏。** Host 在每条自检返回路径（成功、407、5xx、非法 URL、网络错误）都带上
  `target`，合法 URL 只保留 `origin + pathname`；userinfo、query、fragment 不会进入
  `target`、error 或诊断文本。非法目标也会脱敏并截断。
- **死规则补漏。** 设置页现在会标出 `host:port`、杂散 `*` 与单独的 `*.`；
  合法写法 `example.com`、`*.example.com`、`*`、`[::1]` 不受影响。
  Host 与设置页共用 `src/host-rules.ts` 的解析、匹配与死规则分类，警告不阻止保存。
- **保存失败置顶提示。** 写入失败时字段回滚，页面顶部显示原因和关闭按钮；
  下一次成功写入或关闭后消失，多次失败只保留最新一条。
- **诊断脱敏。** 保存成功与失败都不再拼接字段值；密码字段固定显示「值已隐藏」，
  失败消息中的已知密码与其他 URL 凭据也会被清除。

### 保持不变

- 每个 provider 各自持有 dispatcher；流惰性消费与 fail-closed 语义不变。
- 代理端点、目标规则、自检目标仍是 volatile 设置；保存立即对新请求生效。
- `lastUse`、route token、`lastChecks` 未修改；「最近调用」仍按既有规则保留历史。
- 不新增 schema 字段，不新增 toast / 全局通知系统，不增加密码显示切换或批量确认框。

### 已知限制

- `testUrl` 的校验是提示性的：非法候选会保存，但对应自检会失败。
- `testUrl` 超过 5 个时只有前 5 个生效。
- 死规则仅警告、不拒绝写入；Host 的匹配语义与 0.5.1 一致。
- 全局设置只保存 `testUrl` / `localDirect`；`lastUse` 的配置绑定留给 0.6.1。

### 验证

- 248 个用例通过（`npm run verify`：typecheck + build + test），较 0.5.1 的 218 个增加 30 个。
- 新增覆盖：真实 settings form 的顶层字段与默认值、全局块渲染与两条写入路径、
  恢复默认、非法 / 超限提示、全局编辑清空全部结果、测试前冲刷、全局写失败回滚；
  自检 status / target / cached 渲染、旧 payload 兼容、合法 / 非法 URL 脱敏矩阵、
  网络错误不回显原始目标；共享 host-rules 矩阵与死规则警告但可保存；
  保存失败置顶提示、成功清除、关闭、连续失败只留最新一条、密码不出现在诊断。
  另加：慢速成功不被染成失败色、状态码不继承延迟颜色、目标来源三种取值、
  旧 payload 不显示状态码。

### 升级

无字段迁移。0.5.1 的 `cordis.patch.yml` 可直接使用；如需调整 `testUrl` /
`localDirect`，现在可以直接在设置页操作，不必再手改 YAML。

### 安装

```sh
dsh plugin --profile desktop add dsh-provider-proxy
```
