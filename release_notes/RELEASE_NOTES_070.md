## v0.7.0

设置页体验增强：密码可临时显示、Host 目录缺失有解释、批量操作带计数并在覆盖前确认。
无 schema 变更，0.6.1 配置无需迁移。

### 改了什么

- **密码显示 / 隐藏。** 默认代理区块和每张 provider 卡片的密码输入内部右侧都增加了眼睛图标切换。
  它只改变输入框的 `type`，不会改写密码值，也不会写设置；默认块与各卡片的状态彼此独立。
  默认块的显示状态与 provider id 分离，即使真实 provider 名为 `default` 也不会串状态。
  同时把密码和用户名输入的 `autocomplete` 改为 React 的 `autoComplete` 拼写。
- **Host 目录缺失提示。** Host 目录读取成功时，如果某个已保存的 provider 完全没有出现在
  原始 `published` 列表中，就在「连接诊断」里列出它，并说明代理配置仍会保留。提示使用中性色，
  不改变卡片状态、不阻断保存。`live: false` 表示目录中存在但当前未激活，不算缺失。
- **批量操作更明确。** 「所有 provider 使用默认代理」按钮显示目标数量，数量取全部 provider，
  不受过滤框影响。卡片上的「设为默认代理」在默认端点可用且已有继承卡片时，会先确认是否覆盖；
  取消不写入、不改草稿，没有继承卡片时不弹窗。

### 行为变化

- 密码默认仍隐藏；点击密码框内的眼睛图标后仅在当前页面会话内以明文展示，再次点击恢复隐藏。
- Host 目录读取中或读取失败时不会显示缺失提示；目录恢复后提示自动消失。
- 覆盖默认端点需要一次确认；批量操作仍然是一条写入，不拆成逐 provider 写入。

### 验证

- `npm run verify`：typecheck + build + 全部测试。
- 新增覆盖：密码切换只改 type 且不写设置、默认块与卡片状态独立（含 id 为 `default` 的 provider）、
  密码与用户名的 React `autoComplete` 拼写、图标按钮位于密码字段内且有可访问名称；
  N7 原始 published 比较、`live: false` 不算缺失、加载 / 失败不误报；
  N8 计数不受过滤影响、确认 / 取消两条路径、无需确认场景、单次批量写入。
- 真实 DSH Desktop 手工冒烟需在发布前完成：密码显示切换、目录缺失提示、批量计数与覆盖确认。

### 升级

无字段迁移。0.6.1 的 `cordis.patch.yml` 可直接使用。

### 安装

```sh
dsh plugin --profile desktop add dsh-provider-proxy
```
