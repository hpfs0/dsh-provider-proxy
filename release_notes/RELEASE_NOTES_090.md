## v0.9.0

多代理预设与配置生态：命名预设库、常见客户端一键导入、官方上游域名模板、配置 JSON 备份与恢复。
扩展 schema（`proxyProfiles` 与 `profileId`），0.8.0 配置**无需迁移**，原样可用。

### 改了什么

- **多代理端点预设库 (N14)。** 页面新增「代理预设」折叠区，可添加 / 重命名 / 删除命名端点；
  每张卡片的「使用默认代理」复选框升级为端点来源下拉：`独立自定义配置` /
  `预设：默认预设 (Default)` / `预设：<你的预设名>`。预设被修改时，所有绑定它的卡片自检结果立即失效。
  删除仍被使用的预设会先提示依赖的 provider 名称。
- **常见客户端一键导入 (N15)。** 在默认代理区块、预设行与卡片端点处均可选择
  `Clash / Mihomo (7890)`、`Clash Verge / Meta (7897)`、`V2Ray / Xray HTTP (10809)`、
  `V2Ray / Xray SOCKS5 (10808)`；协议 / 主机 / 端口一次写入，仍走既有校验。
  另有「从环境变量」一项，读取 Host 进程的 `HTTPS_PROXY` / `HTTP_PROXY` / `ALL_PROXY`。
- **官方上游域名模板 (N16)。** OpenAI / Anthropic / Google / DeepSeek 卡片的高级规则区出现
  「载入官方上游域名」药丸，一次写入 `onlyHosts`，保留已有自定义主机，且不会产生死规则。
- **配置 JSON 备份与恢复 (N17)。** 页面顶部提供「备份配置 / 恢复配置」：导出前逐次询问是否包含代理密码
  （默认不含），文件名形如 `dsh-proxy-backup-2026-10-27.json`；导入先校验结构与字段类型，
  确认后以**一次**设置写入覆盖 `providers` / `proxyProfiles` / `defaultProxy` / `localDirect` / `testUrl`。
- **紧凑视图改为三行 (N18)。** 每行第一行展示 provider 名称 / id / 实际生效的端点 / 最近调用，
  第二行集中所有操作（启用开关、**端点来源下拉**、测试、编辑），第三行专门显示自检结果
  （延迟、HTTP 状态、出口 IP 或失败原因）。结果独立成行，测速与报错都不会挤动下拉框和按钮。
  视图模式与状态筛选会记住上次选择（存于浏览器 `localStorage`，不写入配置文件），
  离开再回到本页仍保持紧凑视图。

### 布局与交互修整

- **统一的排版尺度。** 页面分为「页面设置」与「Provider 列表」两组；默认代理、代理预设、
  全局设置、备份恢复归为页级设置，状态筛选 / 搜索 / 批量测试 / 视图切换合并为列表工具栏并紧贴列表上方，
  不再被四个面板隔开。所有区块统一 10px 圆角与四级内边距。
- **卡片控件对齐。** 「启用」开关与「端点来源」下拉排在同一条控件行，形态一致（标签在上、控件在下）。
- **状态筛选按钮的选中态重做。** 未选中为纯文字，选中为实心药丸；悬停只给淡背景，不再与选中态撞色。
  并修掉了「激活过一次再取消」后残留边框的问题——原因是 React 内联样式中 `border` 简写与
  `borderColor` 长写混用，取消时 React 删除该键导致边框回落到 `currentColor`。
- **自检不再复用过期结果。** 修改端点后立刻点「测试」曾可能走旧 dispatcher 而误报「通」
  （例如旧代理对 `api.deepseek.com` 返回 401）；现在会先用当前设置重建预期路由比对，不一致即按新配置临时构建。
- **自检不再复述已失效的拒绝原因。** 曾经半填过密码再清空时，会一直报「配置了代理密码但没有用户名」；
  现在无可用路由时一律用当前设置重新校验，只报告仍然成立的问题。
- **预设取名改为页面内输入。** Electron 不实现 `window.prompt`，原实现点击「添加预设」没有任何反应；
  改为内联输入框（Enter 提交），添加后自动展开预设区，重名或空名会显示原因。

### 行为变化

- **Schema 扩展**：顶层新增 `proxyProfiles`（名称 → 端点），路由新增 `profileId`（默认 `''`）。
  两者缺失时按空处理，`defaultProxy` 与其原有的 `useDefault` 语义完全不变。
- **绑定优先级**：`profileId` 非空时优先于 `useDefault`；页面在选择预设时会同时把 `useDefault` 置为 false。
- **缺失预设是拒绝，不是回退**：绑定到已删除的预设时，该 provider 不走代理并在卡片与诊断中说明原因。
- **预设编辑即失效**：路由指纹与自检缓存键改为使用**生效端点**，改预设等同于改卡片自身端点。
- **环境变量只取地址**：凭据从不进入 `/dsh-provider-proxy/providers` 的响应，只用布尔值提示"带了凭据，请补填"。
- 端点来源下拉**始终存在**（含「默认预设」一项），没有自定义预设时它只比原来的复选框多出两个选项；
  原有的 `useDefault` 语义与写盘路径完全不变。
- **视图偏好存于浏览器本地**：视图模式与状态筛选记在 `localStorage`（键 `dsh-provider-proxy:view`），
  不写入 `cordis.patch.yml`；存储不可用或值损坏时静默回落到默认值。

### 升级

无字段迁移。0.8.0 的 `cordis.patch.yml` 可直接使用；`proxyProfiles` 与 `profileId` 会按默认值补齐。
若此前用某个 `defaultProxy` 服务多个 provider，可以把它改成命名预设，再让各卡片分别绑定。

> 若升级后看不到新界面，请确认 `web` profile 也重新安装过：
> `dsh plugin --profile web add dsh-provider-proxy`。桌面版从目录安装时会跟随源码重建。

### 安装

```sh
dsh plugin --profile desktop add dsh-provider-proxy
```
